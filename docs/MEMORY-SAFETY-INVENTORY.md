# Memory-safety worklist

**Start with the bytes an archive supplies.** Opening a ZIM, decoding a cluster, querying an embedded index, and rendering the resulting article are four separate operations. Switching to the Rust ZIM and Xapian readers would retire the current C++ reader and search code once every consumer switches. Zimru's current file mapping and codecs, and the platform rendering engines, need their own decisions.

This is a source inventory of Kiwix Workbench at `921327a76df2167d570d9f88f7a14e5c8009bfd5` (2026-11-17). An open box identifies a boundary to work on. It does not identify a confirmed memory bug. Bare Rust module paths in the tables refer to `src-tauri/src/`. The `native/` and `vendor/` directories sit under `src-tauri/`. Swift and Kotlin plugin filenames refer to [the mobile plugin](../src-tauri/plugins/tauri-plugin-kiwix-mobile).

## Archive and article paths

|---|---|---|
| ☐ A1. Archive access | `archive.rs` owns the opaque handle and result buffers from [archive.cpp](../src-tauri/native/archive.cpp) through [archive.h](../src-tauri/native/archive.h). | ☐ A2. Search and suggestions | `archive.cpp` uses libzim's Searcher and SuggestionSearcher, backed by Xapian. Title-prefix fallback also matters when an index is absent. [Reader architecture](ARCHITECTURE.md) · [Media paths](VIDEO-FORMATS.md) |

The [current SDK patches](FORKS.md) document retained descriptors, large offsets, range reads and cluster caching that the migration must preserve. Check the packaged SDK dependencies too, including ICU, zlib, libzstd and liblzma where linked. The separate [xapianbuilder snapshot](https://github.com/jasontitus/xapianbuilder/blob/13ff368991850f35ecb2e60037c6385d9992cbdc/build.rs) still builds a C++ bridge for producing indexes. It is outside the app's runtime and the proposed query reader has not been assessed here. The Zimru snapshot also has optional C exports and a default-enabled writer with its own mapping. A Rust-to-Rust reader integration can leave both out.

### Progress since the 2026-11-17 snapshot

`942c36306b`, `84fd93e7de`, `cdfdf64478` and `7b50d62763` (2026-11-19) removed 20 `unsafe` matches from nine
files, six of which became unsafe-free (`239` → `219` matches; `42` → `36` files):

- **B3, exclusive-rename, volume-space and lock subset.** `publication::platform_publish{,_in}`,
  `maps::partials::capture_partial`, `library_files::move_exclusive`,
  `localswarm::storage::rename_directory_noreplace` and `torrent::publication::move_publication_entry` now use
  `rustix::fs::renameat_with(…, NOREPLACE)`,
  matching `library_root::publish_exclusive`; `fs_ext::volume_space` uses `rustix::fs::statvfs` and
  `try_flock_*` uses `rustix::fs::flock`. No-replace is still filesystem-enforced, the Linux old-kernel
  `link(2)` fallback is preserved, the volume arithmetic and NUL diagnostic are unchanged, and
  `EWOULDBLOCK` still maps to `WouldBlock`. The Windows arms, file identity and the rest of B3 remain open.
- **B4, document-provider descriptor subset.** `provider_reference`'s native `retain` now duplicates the
  lease-owned descriptor with `rustix::io::fcntl_dupfd_cloexec` and probes seekability with `rustix::fs::tell`;
  only the documented `BorrowedFd::borrow_raw` claim remains. Lease lifetimes, revoke/regrant, backup flags,
  bookmark scope and the Swift `unsafeBitCast` delegate chaining remain open.
- **SAFETY documentation.** `dd2c6738f5` added 25 missing `SAFETY:` comments to Apple share, PDF
  handoff/render/print and notification boundaries, naming pointer lifetime and exactly-once ownership. No
  behavior change. An eight-line audit still finds 161 of 218 code blocks without one.
- **B10, diagnostic clocks.** `maps::Control::chunk_sha256` and the ignored throughput benchmark now read
  `cpu_time`'s helpers; no `getrusage` or raw `CLOCK_THREAD_CPUTIME_ID` call remains in `src/`. Test-only
  FIFO/interface/ACL calls, the probes and the JNI entry points remain open.

Host check, Clippy, the publication/move/capture/composer, connector and library-recovery tests, and an
Android lib type check were exercised; iOS, Linux, device and sanitizer verification were not. See the
[review's 2026-11-19 section](RUST-UNSAFE-REVIEW.md#follow-up-implemented-2026-11-19).

The eight handwritten Rust thread-safety assertions in the app deserve explicit sign-off. They cover `archive::Handle` (Send), `RawConnection` and `RawListener` (Send and Sync each), `power_activity::Token` (Send), and the Windows connector's `Descriptor` (Send and Sync). Retirement requires checking who can use each handle concurrently, who may destroy it, and whether native callbacks can still run at that point. The [earlier Rust review](RUST-UNSAFE-REVIEW.md) records completed reductions, including effective-UID checks and Linux app-side peer credentials.

## Refresh and closure

Run these from the repository root. The first search includes tracked tests and vendored code. The second also catches older-style declarations and exports whose signatures lack the Rust keyword. Inspect cfg gates, comments, macro expansions and the matching native implementation before classifying a hit.

```sh
git grep -n -w unsafe -- '*.rs'
git grep -nE 'extern "(C|system)"|no_mangle|mobile_entry_point' -- '*.rs'
git ls-files -- '*.c' '*.cc' '*.cpp' '*.h' '*.hpp' '*.m' '*.mm' '*.swift' '*.kt' '*.java'
git grep -nE 'unsafeBitCast|[Uu]nsafe(Pointer|Mutable|Raw|Bytes|Buffer)|assumingMemoryBound|withMemoryRebound|objc_(get|set)AssociatedObject|@_cdecl' -- '*.swift'
git status --short --untracked-files=all
cargo tree --manifest-path src-tauri/Cargo.toml --locked --target aarch64-apple-darwin -e normal,features
```

Repeat the last command for the packaged target and feature selection, and for `kiwix-mcp/Cargo.toml` on desktop. Consult [the app manifest](../src-tauri/Cargo.toml), [native build script](../src-tauri/build.rs), [mobile plugin](../src-tauri/plugins/tauri-plugin-kiwix-mobile), and [packaging guide](PACKAGING.md) for non-Cargo inputs.

To close a box, record the implementation commit, targets and features, what native or unsafe code remains reachable, comparison results and independent review. For platform-owned boundaries, record the isolation/lifetime guarantee and the exercised failure case. For this baseline, the locked app dependency graphs were inspected for ARM64 macOS, iOS and Android, ARMv7 Android, and x86-64 Linux and Windows. Each includes AWS-LC, ring, bundled SQLite bindings, sherpa-onnx bindings and the Rust bzip2 backend on at least one normal dependency path. The ARM64 Apple and Android graphs also include `sha2-asm`. This baseline is source-traced. It includes no new device tests, sanitizer results or binary-level certification.
