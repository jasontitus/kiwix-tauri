# Apple Nearby value boundary

Connection setup sends a bounded Bonjour instance by value with explicit peer-to-peer, isolation and interface settings. Network.framework returns the effective local address and its route description by value. The address used to check that an interface is still assigned also crosses as a value. Both sides check the sizes of the initialized C records and their byte-field offsets. Rust validates the address family and the route text before using the results. The native route predicates still check the live interface, address family and IPv6 link-local scope.

TLS setup receives Foundation `NSData` created through the typed Rust binding. Native initialization copies the inputs into immutable objects for import and publishes the identity and pin once, with release/acquire ordering. macOS verifies the in-memory private key against the certificate. iOS imports the PKCS#12 and compares its leaf to the pinned certificate. Pending reads, writes and listener callbacks continue to use the existing object and request ownership rules.

The production Rust census goes from 165 to 159 blocks. Six are removed from `apple_transport.rs`, leaving four there for start, listen, receive and write. The count covers `src-tauri/src` and `kiwix-mcp/src`, with 146 blocks in the app and 13 in the Windows relay. The separate 41 unsafe declarations are unchanged. This is a source count across platforms. The app still needs the native Network.framework, Security and DNS-SD adapters and the dependency code that backs native callback objects.

Independent review found that the proposed Nix interface-name wrapper treats Darwin's `NULL` failure as a different sentinel. The production discovery lookup stays on its checked implementation. Review also identified that passing a mutable Foundation subclass could otherwise alter a retained certificate. Validation and publication now use the same immutable copy. The reviewer verified the resulting three-path source manifest on `d8952206de7911f17686a71eba7379cedeadc159`, SHA-256 `a0301ede2185f1f961585058f736666ca4ea679c53ab4213b09671032d95afaa`, and independently compared the Rust and Clang ARM64 ABI declarations.

## Runtime and platform checks

The arm64 Mac application passed 24 focused transport, read-request and discovery tests. The new regressions exercise initialized returns for missing handles and checked IPv4 and IPv6 conversion. Both baseline and candidate passed the live IPv6 link-local address check and concurrent native QUIC requests, including reading two archive responses after completing one transport. The same-Mac network cases used an active LAN interface and ephemeral Bonjour services. The runner verified that all owned temporary profiles were empty after each process. The native AddressSanitizer and UndefinedBehaviorSanitizer fixture passed 12 checks with empty stderr.

Five alternating Mac pairs each ran a complete Bonjour and QUIC inventory process with 64 live route receipts. All passed. After excluding the warm-up pair, median wall time was 1.203 s before and 1.218 s after, with a median paired increase of 4.72%. Median process CPU was 69.93 ms before and 64.67 ms after, with a median paired decrease of 7.44%. The measurements cover launch, discovery, transfer and cleanup in unoptimized app test binaries. They give limited evidence on the cost of the new value handoff. [Exact artifacts and individual runs](../benchmarks/2026-11-19-apple-nearby-values.json)

Both iOS ARM64 app-library targets passed locked offline compile checks with `custom-protocol`. Those checks cover the device and simulator builds. iOS runtime, peer-to-peer behavior on separate devices and archive speed against libzim remain open.
