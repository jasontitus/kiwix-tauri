# Memory-safety checkpoint

The app still runs native code on untrusted content. A fresh Mac release build at `541725a` counted 86 unsafe Rust sites in the app crate and 17,255 across 420 target-side packages. Moving Bonjour discovery callbacks to operation numbers removed five app sites. The previous connection and listener handle migration removed eleven. The acceptance target trusts the OS and standard runtime and includes application code and its dependencies. The main remaining paths include native speech inference, rendering and media, Nearby connections and discovery, platform document handoffs and bundled database and networking libraries. [Boundary inventory](../MEMORY-SAFETY-INVENTORY.md)

## Changes saved privately

The [voice and receive integration](https://github.com/jasontitus/zimru-xapian/commit/f1a6c0890a3348982a4cb3588d85ef86f54296af) combines the Android factory-voice producer, reviewed voice installer and Apple Nearby receive change. The final three-file Linux test correction exercises the production profile layout. The first combined Apple packages used `bec2658`. The [subsequent Apple stream fix](https://github.com/jasontitus/zimru-xapian/commit/ce566218b035613cfd23ee34ded01ee6083bb113) delivers a final payload and preserves clean end-of-stream on the following read.

- The voice installer authenticates downloaded and bundled inputs, uses safe Rust bzip2 decompression and journals installation and removal. It preserves an existing installation when recovery cannot establish which model files belong to the app. Android treats an inconclusive factory-asset lookup as retryable. Native sherpa-onnx and ONNX Runtime still process text and models. [Installer checks and decoder timings](2026-11-18-voice-pack-decoder.md)
- Apple Nearby now binds each incoming read to a single-use ID, validates its size and retires the ID on cancellation. Native code returns a typed dispatch object and the request ID in place of a raw byte pointer and heap-owned Rust callback context. The [next Apple revision](https://github.com/jasontitus/zimru-xapian/commit/09e57a9ec86c3fd828f19b4aa638f490c42606ae) also replaces the raw callback contexts for sends, connection and listener readiness, and incoming connections. One dispatch-owned copy carries each outgoing piece. The [handle migration](https://github.com/jasontitus/zimru-xapian/commit/26ced3277ccf3a9f0bf0a6197888a8a50d3344bd) replaces raw connection and listener pointers with integer IDs, removing four manual thread-safety declarations. Native connection state, buffer traversal, block support and DNS-SD still require review. [Apple receive tests and timings](../benchmarks/2026-11-18-apple-nearby-reads.md)
- The Rust Bonjour discovery worker now passes an operation number through DNS-SD. It accepts a callback only during the matching operation on the owning thread. On both macOS and the iOS simulator, a reader found a temporary service, observed its withdrawal and found its replacement after restart. At `e46993d`, the native connection resolver also gives DNS-SD a fresh number for each service or address lookup and retires it before deallocating the SDK reference. The Mac release test executable exercised this path through real Bonjour and QUIC. On the iOS simulator, a separate resolver probe verified host rejection, route fallback and recovery after late registration. [Discovery checks and measurements](../benchmarks/2026-11-18-bonjour-callbacks.md)
- The [next Apple route fix](https://github.com/jasontitus/zimru-xapian/commit/d0c967cd449c3fdeb66f5e2fdac19e7f2dd90d4c) checks the declared size of a DNS address reply, copies the complete IPv4 or IPv6 address and normalizes its length before checking whether the peer is on the selected local network. The endpoint receives those same checked bytes. The Mac bridge fixture passed under AddressSanitizer and UndefinedBehaviorSanitizer. All seven native fixture groups also passed on the ARM64 iOS simulator. A live Mac DNS-SD lookup supplied IPv4 and IPv6 loopback addresses. Both copies retained the returned IP address and the port supplied by the test. An independent check passed the copied addresses into Network.framework and verified the resulting endpoints after overwriting the source buffers.
- The app still pins the MIT archive reader at `ff8b0ab` and GPL search at `380d84d`. These changes affect the GPL app. The optional MIT reader performance switch remains deferred. [Reader performance follow-up](../MEMORY-SAFETY-INVENTORY.md#performance-follow-up)

## Performance and open work

Ten alternating Mac comparisons per archive covered 24 full articles per fresh process. The signed `3e9e976` Mac app served Climate in 36.16 ms versus 35.99 ms for the libzim app. Wikipedia 100 took 63.91 ms versus 61.40 ms. All 960 responses preserved the original article bytes. On Linux the same full-article workloads took 95.30 ms versus 89.51 ms on Wikipedia 100 and 60.19 ms versus 54.46 ms on Climate. The earlier direct-library comparison still favored libzim on the random-article workload on all four platforms. [Complete-article measurements](../benchmarks/2026-11-18-served-articles.md) · [Direct reader timings](../benchmarks/2026-11-18-retained-clusters.md)

The next Nearby work covers SDK-owned hostnames in the connection resolver and borrowed strings and TXT records in the Rust discovery adapter. The optional reader setting awaits real-device measurements. Reusing the decoder workspace across real clusters produced mixed Mac medians, so the production reader still constructs a decoder per cluster. The Mac handle benchmarks found a 10.5% increase for fragmented 256 KiB reads and a 0.40 µs decrease per piece for eight outstanding 256 KiB sends. On the iOS simulator an 81-byte QUIC round trip showed a 15.7% paired slowdown in the first run and a 0.3% paired improvement in the repeat. Physical transport throughput remains open. [Handle timing and lifetime checks](../benchmarks/2026-11-18-apple-nearby-handles.md)

An unshipped MIT decoder experiment moved the entropy-table updates ahead of copying a sequence. Direct random reads became faster on both Mac archives and slower on both Linux archives. In the signed Mac app, the change improved median complete-article time by 1.2% on Climate and 0.4% on Wikipedia 100. The app continues to use MIT `ff8b0ab`.
