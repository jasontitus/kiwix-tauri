# Memory-safety checkpoint

The app still runs native code on untrusted content. A fresh Mac release build counted 91 unsafe Rust sites in the app crate and 17,260 across 420 target-side packages. Replacing raw Apple connection and listener handles with non-recycled IDs removed eleven app sites from the previous release build. The acceptance target trusts the OS and standard runtime and includes application code and its dependencies. The main remaining paths include native speech inference, rendering and media, Nearby connections and discovery, platform document handoffs and bundled database and networking libraries. [Boundary inventory](../MEMORY-SAFETY-INVENTORY.md)

## Changes saved privately

The [voice and receive integration](https://github.com/jasontitus/zimru-xapian/commit/f1a6c0890a3348982a4cb3588d85ef86f54296af) combines the Android factory-voice producer, reviewed voice installer and Apple Nearby receive change. The final three-file Linux test correction exercises the production profile layout. The first combined Apple packages used `bec2658`. The [subsequent Apple stream fix](https://github.com/jasontitus/zimru-xapian/commit/ce566218b035613cfd23ee34ded01ee6083bb113) delivers a final payload and preserves clean end-of-stream on the following read.

- The voice installer authenticates downloaded and bundled inputs, uses safe Rust bzip2 decompression and journals installation and removal. It preserves an existing installation when recovery cannot establish which model files belong to the app. Android treats an inconclusive factory-asset lookup as retryable. Native sherpa-onnx and ONNX Runtime still process text and models. [Installer checks and decoder timings](2026-11-18-voice-pack-decoder.md)
- Apple Nearby now binds each incoming read to a single-use ID, validates its size and retires the ID on cancellation. Native code returns a typed dispatch object and the request ID in place of a raw byte pointer and heap-owned Rust callback context. The [next Apple revision](https://github.com/jasontitus/zimru-xapian/commit/09e57a9ec86c3fd828f19b4aa638f490c42606ae) also replaces the raw callback contexts for sends, connection and listener readiness, and incoming connections. One dispatch-owned copy carries each outgoing piece. The [handle migration](https://github.com/jasontitus/zimru-xapian/commit/26ced3277ccf3a9f0bf0a6197888a8a50d3344bd) replaces raw connection and listener pointers with integer IDs, removing four manual thread-safety declarations. Native connection state, buffer traversal, block support and DNS-SD still require review. [Apple receive tests and timings](../benchmarks/2026-11-18-apple-nearby-reads.md)
- The app still pins the MIT archive reader at `ff8b0ab` and GPL search at `380d84d`. These changes affect the GPL app. The optional MIT reader performance switch remains deferred. [Reader performance follow-up](../MEMORY-SAFETY-INVENTORY.md#performance-follow-up)

## Performance and open work

Ten alternating Mac comparisons per archive covered 24 full articles per fresh process. In the latest Mac run the signed app served Wikipedia 100 in 123.66 ms versus 121.10 ms with libzim. Climate took 69.53 ms versus 71.38 ms. The relative timings varied across the three Mac runs. On Linux the same full-article workloads took 95.30 ms versus 89.51 ms on Wikipedia 100 and 60.19 ms versus 54.46 ms on Climate. The earlier direct-library comparison still favored libzim on the random-article workload on all four platforms. [Complete-article measurements](../benchmarks/2026-11-18-served-articles.md) · [Direct reader timings](../benchmarks/2026-11-18-retained-clusters.md)

Continue with Bonjour callback contexts, route address buffers and the remaining platform and dependency boundaries in the inventory. Verify real-device performance before enabling the optional reader setting. The Mac handle benchmarks found a 10.5% increase for fragmented 256 KiB reads and a 0.40 µs decrease per piece for eight outstanding 256 KiB sends. On the iOS simulator an 81-byte QUIC round trip showed a 15.7% paired slowdown in the first run and a 0.3% paired improvement in the repeat. Physical transport throughput remains open.
