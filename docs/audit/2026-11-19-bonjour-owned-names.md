# Checked names in Apple Bonjour discovery

The Apple discovery worker gives `DNSServiceConstructFullName` its own 1,009-byte buffer as required by the SDK. Rust now reads the buffer with checked C-string and UTF-8 parsing. It requires the first NUL within the first 256 bytes, preserving the 255-byte limit for an accepted ID. The worker uses the same escaped name and interface index to match an announcement and its withdrawal. For direct route selection, `if_indextoname` writes into its own `IF_NAMESIZE` array. The worker checks the native null return, parses the initialized bytes and checks the existing `awdl` and `llw` byte prefixes without allocating. [Discovery and interface code](../../src-tauri/src/localswarm/ios_discovery.rs)

The change removes two raw-pointer read expressions in app-owned code. The two SDK writes remain. The SDK still owns strings and TXT bytes borrowed by callbacks, and Rust still calls DNS-SD to manage the service references and poll their file descriptors. The Objective-C++ connection resolver is a separate boundary. [Discovery callback ownership](../benchmarks/2026-11-18-bonjour-callbacks.md)

## Discovery and withdrawal

The standalone release fixture compiled the exact production discovery module. It also used the production discovery facade and publisher validation. Test adapters supplied the few surrounding protocol and transport definitions needed for the fixture, which opened no archive and made no QUIC connection. Two workers used system Bonjour. The fixture bound its socket to a private IPv4 address. For each trial, the runner verified the escaped dotted service name and the complete endpoint encoding from the original instance. It observed a first registration and withdrawal, then a second registration at the same name with a new token. After attempting withdrawal with the old token, it restarted the reader and freshly observed generation 2. It then withdrew the second record and waited for both workers to stop. The first publication used the system host, and the second used an explicit address for the fixture's bound socket.

Both revisions passed on ARM64 macOS and an owned ARM64 iOS 26.5 simulator. The Mac ran one smoke pair followed by six alternating measurement pairs. The simulator ran two pairs. The runner checked successful exit and cleanup for each process. Simulator removal was confirmed. The candidate worker also passed a compile check for ARM64 iOS device. [Binary identities and trial records](../benchmarks/2026-11-19-bonjour-owned-names.json)

The complete app library passed locked compile checks for iOS ARM64 device and simulator with `custom-protocol` enabled. The Mac release app test binary passed all 11 Apple discovery tests, including the new checks for NUL termination, UTF-8, the byte boundary and missing or ordinary interface names. The broader loopback-restricted LocalSwarm run passed 130 tests and recorded one failure when the revocation test could not reach the Bonjour daemon. The same binary passed that test with regular system Bonjour access. It also passed the live native route and concurrent QUIC library request tests. The native test profiles were removed. Physical-device behavior and application packaging are outside these checks. [App artifacts and test receipts](../benchmarks/2026-11-19-bonjour-owned-names.json)

## Performance

The median paired ratio for the complete Mac discovery lifecycle was 0.970. The baseline median was 2,700.861 ms and the candidate median was 2,653.702 ms. The two simulator pairs had candidate/baseline ratios of 1.439 and 1.043. Their interval includes OS registration, interface queries, repeated discovery and withdrawal, and worker shutdown. The simulator sample is too small to determine whether the whole lifecycle got slower.

On the Mac, a separate release fixture timed the old and new parser with the same owned buffers. The timer covers parsing, allocating and freeing the accepted name or rejecting it. It excludes the SDK write and network activity. The median of eight batches of 400,000 calls was 132.787 ns before and 92.385 ns after for a representative escaped name. At 255 bytes the medians were 373.670 ns and 150.295 ns. Rejecting 256 bytes took 341.285 ns and 31.436 ns. These measure local parsing on this host. Mobile-device latency and archive reader parity require separate measurements. [Individual samples and fixture identity](../benchmarks/2026-11-19-bonjour-owned-names.json)

## Independent review

Review covered the SDK output capacity, byte limits and UTF-8, and add/remove identity and lifetime. The initial patch proposed using the pinned nix interface-name wrapper. The reviewer identified its mismatch with the native null failure sentinel. The final patch preserves the explicit null check and uses the owned slice for the name read. Review also caught reused Mac binaries in an early fixture build. The measured runs use separately compiled binaries with distinct hashes and exact source depfiles. Review checked the revised runtime fixture, including ownership, hard timeouts and simulator removal. [Whole-app inventory](../MEMORY-SAFETY-INVENTORY.md)
