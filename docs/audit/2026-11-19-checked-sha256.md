# Checked SHA-256 compression

The app's RustCrypto callers use a local copy of SHA-2 0.11.1. The normal app lockfile drops `sha2-asm` 0.6.4. On AArch64 and x86 the SHA-256 compressors build vectors from checked slices and initialized integer arrays. The unrolled software compressor indexes its round constants directly. These three SHA-256 modules forbid unsafe Rust. CPU feature dispatch still uses a narrowly scoped unsafe call on hardware that provides the required instructions. [Published source and bundled attribution](../../src-tauri/licenses/sha2/SOURCE.txt)

The same streaming checks cover downloads, map prefixes, library and torrent file ownership, and Nearby manifests and authentication. The app still emits raw 32-byte digests or lowercase hexadecimal as required by each caller. The Android WebView script injection uses the same vendored SHA-256 provider. The digest API upgrade also adds a shared `Write` adapter for existing serializers and the retained-file cleanup read. That read keeps its size-plus-one limit, retained file and byte-count check.

The published package and its MIT and Apache license texts are retained. The AArch64 files carry the original Mbed TLS attribution and the local changes carry prominent notices. The vendoring lives in the application source tree. Zimru and Glass retain their separate license and source histories.

## Verification and scope

The independent source review inspected 65 modified and new paths against base `69f2b9e1ef4fb15fe2bdaa8cab560254e3292286`. The sorted SHA-256 and path manifest of those files hashes to `41ba73554e84f74c06220efde36b4d5e4627837525382275c92043ffbe1eea2d`. The review caught an incompatible standalone Wry lockfile, missing modified-file notices, and a mismatched RISC-V SHA-512 selector. The final source review checked all three fixes. RISC-V was reviewed from source. The Wry standalone lock selects published SHA-2 0.11.0 at its declared Rust floor. The app locks the modified 0.11.1.

On ARM64 macOS the upstream SHA-2 crate passed 14 known-answer, random and serialization tests and two documentation tests in both the default and explicitly selected ARM configurations. The differential runner also passed with the default ARM and forced software SHA-256 backends. It covers pinned SHA-2 0.10.9 output, padding and slice alignment, streamed and cloned states, arbitrary initial compressor state and empty inputs. A separate test matches independent digests immediately before, at and after the 4 GiB byte boundary.

The same differential and 4 GiB tests passed on the Ubuntu x86-64 build host using the software compressor. QEMU 8.2.2 exposed SHA and SSE4.1. The normal CPU selection and the explicitly selected x86 SHA backend both passed the short differential tests. The explicit backend also matched both real archive digests. The emulator timing is outside the performance comparison. The optimized Rust app library tests passed 1,259 cases on macOS with 25 ignored and 1,242 on Ubuntu with 16 ignored. The app also passed compile checks for iOS ARM64, iOS simulator ARM64, Android ARM64 and Android ARMv7.

The Ubuntu release binary and AppImage matched the recorded service responses for an ordinary archive, reopening, a split archive and ranged image reads. The AppImage verifier checked the packaged resources against their source files. The final reviewed source differs from the earliest tested snapshot by the standalone Wry lock, dependency change notices and the RISC-V-only feature gate. Those changes leave the tested application code and target selection equivalent.

An independent reviewer checked 18 Nearby authentication outputs against the previous implementation and Python's HMAC. All seven Wry script-injection tests passed, including the content-security-policy hash. The reviewer also exercised the actual application dependency configuration. The locally signed Mac bundle passed signature verification and contained the three byte-matched SHA-2 license and source files.

In signed Mac tests, both builds accepted the real Climate Change and Wikipedia 100 archives with their independent advertised SHA-256 values. Both rejected a mismatched advertised checksum without publishing either archive. The checked build reopened each prior-build download record. Independent file reads confirmed the same digest. The two builds and the historical libzim reference returned matching previews and normalized MHTML exports.

## Remaining boundaries

A standalone forced-warning compile emitted one unsafe Rust site for SHA-256 in the default ARM64 crate configuration. That call enters the hardware compressor after checking CPU features. No SHA-256 site was emitted in the forced software configuration. SHA-512 still emitted six sites in both builds. These diagnostics cover the SHA-2 crate only. The vendored crate includes separate accelerators for WebAssembly, RISC-V and LoongArch outside the exercised app targets. CPU detection and generic digest buffering have separate dependency boundaries. The old SHA-2 version still appears through Tauri's build tools and Snow's dependency graph. Zimru's runtime XZ reader uses a different LZMA feature set from the host packaging ZIP dependency. Actual performance on physical Android and iOS hardware remains open.

cargo test --locked --release --manifest-path src-tauri/vendor/sha2-0.11.1/Cargo.toml --all-features
cargo test --locked --release --manifest-path scripts/check-sha256-loads/Cargo.toml -- --include-ignored
RUSTFLAGS='--cfg sha2_256_backend="soft"' cargo test --locked --release --manifest-path scripts/check-sha256-loads/Cargo.toml -- --include-ignored
cargo run --locked --release --manifest-path scripts/check-sha256-loads/Cargo.toml -- /path/to/archive.zim
