# Checked iOS route addresses

The iOS bound-peer check and Nearby Wi-Fi snapshot previously accessed native `sockaddr_in` and `sockaddr_in6` members through casts. Darwin can supply a compact netmask that ends inside the IP field. The new decoder checks the record length and family before accessing the field and reads at most the bytes declared for that field. It fills omitted trailing mask bytes with zero, rejects short local address records and rejects default masks for on-link decisions. It keeps the native `in_addr.s_addr` representation used by Nearby Join when storing IPv4 snapshots. The earlier Objective-C++ QUIC fix covers a separate caller. [Swift decoder](../../src-tauri/plugins/tauri-plugin-kiwix-mobile/ios/Sources/RouteIPAddress.swift) · [Swift route policy](../../src-tauri/plugins/tauri-plugin-kiwix-mobile/ios/Sources/MobilePolicy.swift) · [Darwin interface-list contract](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/getifaddrs.3.html)

Rust now sends the address family and integer words to Swift by value. The linker requires a distinct symbol for the new signature, so a stale Swift archive with the old pointer signature causes a link error. Swift validates the tag and IPv4 word width before entering the route check. Rust still normalizes IPv4-mapped IPv6 addresses. The Swift route lock guards the interface index and the list traversal. Nearby still checks the saved interface generation and prefixes before using a snapshot. The decoder relies on Darwin to keep each record readable within its declared length until the interface list is freed. The native socket binding, Swift interface-list traversal and other native route adapters remain in scope. [Rust route caller](../../src-tauri/src/transfer_policy.rs) · [Nearby Join consumer](../../src-tauri/plugins/tauri-plugin-kiwix-mobile/ios/Sources/NearbyJoin.swift)

Compared with `8ce8de949bcc1100cb46786fe3fcccd8d17ecc1f`, this removes one explicit production Rust `unsafe` block and replaces six full-structure IP casts across the two Swift consumers. The Rust count is 117 app blocks and 13 MCP relay blocks, or 130 total, plus 35 separate explicit declarations. Socket binding still uses the `unsafe extern` block that also declares the by-value call.

## Verification

- Four hosted Swift tests passed in an owned ARM64 iOS 26.5 simulator. They covered compact IPv4 and IPv6 masks, bytes beyond the declared IPv4 length, short or mismatched records, valid and invalid by-value address tags, and an unset route. The hosted test target linked the mobile plugin. [Regression tests](../../src-tauri/plugins/tauri-plugin-kiwix-mobile/ios/Tests/RouteIPAddressTests.swift)
- A signed standalone fixture linked the production Rust locality call and Swift entry point. Its SHA-256 was `9c8afdcbcdc8d7640db260674b2bce111f741e93a89f8653e70fce1d6785d100`. It supplied a fixture-selected interface index under the existing lock and used Darwin's live list. It observed one IPv4 and two IPv6 addresses on that interface, including a compact IPv4 netmask. Checks covered on-link matches for those addresses, IPv4-mapped IPv6, invalid route or address arguments, retirement, and rejection of an old Nearby snapshot after reselecting the same index. The fixture exited successfully and the runner confirmed deletion of the owned simulator. The fixture tests self-addresses and a synthetic route lifecycle. Real remote peers, socket binding, live hotspot transitions and physical devices require separate verification.
- Locked, offline app-library checks with `custom-protocol` passed for ARM64 iOS device and simulator under Rust 1.95.0 and Xcode 27 RC. The Swift plugin archives from both builds export the new by-value symbol. The simulator runtime evidence comes from the hosted test and standalone fixture.
- Independent source review checked both Swift consumers, the Rust calling convention, address normalization, list ownership and Nearby Join's use of the native IPv4 word. On ARM64 macOS, the reviewer checked 162 prefix lengths and 26 live interface address/mask pairs, including six compact masks, against an independent calculation. Separate review checked the mobile build inputs, hosted results, simulator fixture and owned-device cleanup.

## Route classification timing

The final optimized simulator fixture ran five batches of 512 successful IPv4 classifications while the iOS device build was running. Timing includes the Rust-to-Swift call, lock, validation and real `getifaddrs` enumeration. The median batch mean was 10.02 ms per call, with batch means from 8.97 to 10.98 ms. A baseline and full-transfer throughput remain unmeasured for this change. [Whole-app inventory](../MEMORY-SAFETY-INVENTORY.md)
