# Reliability, usability, design, maintainability and security review

Date: 2026-11-08. Reviewed starting commit:
`c5a394c202a2054851db5d702ded6f4e80de5bba`.
The starting index and worktree were clean. This report describes this review's
working-tree changes, including newly added tests; it is not release, platform
parity, accessibility compliance, or exhaustive security certification.

## Assessment and scope

The project has substantial explicit safety boundaries: one authoritative
service/store, isolated archive origins, guarded reader messages, transactional
state, no-clobber publication, explicit destructive confirmations, and separate
public sharing/private reading-data protocols. The most important weaknesses
found in this pass are at boundaries between those mechanisms: persistence and
worker admission, published files and delayed import, settings and delayed
native handoffs, and submitted forms and later edits.

Five separate reviewers examined reliability, ease of use, design,
maintainability and security. A sixth reviewer independently checks the combined
changes; authors also cross-review separate batches. The integration owner
coordinates scope, tests, documentation and remaining blockers.

| Perspective | Current code and contracts examined | Limits |
| --- | --- | --- |
| Reliability | HTTP acquisition admission, cancellation, resume, journals, publication/recovery/import, file ownership; BitTorrent/Nearby publication-to-import authority; adjacent map/torrent resume patterns | Native fault-injection regressions cannot yet run in this checkout |
| Ease of use | Library filters/import/search and cancellation; reading list/history; modal confirmation/focus; swipe/keyboard actions; settings autosave; download recovery; storage switching | Source review and execution of real extracted handlers; no mounted UI or assistive-technology acceptance |
| Design | Shell/navigation, archive cards/facets, maps, reader panels, sharing, five platform palettes, text scaling, focus and reduced-motion patterns | CSS/source analysis and computed contrast; no current-run screenshots or rendered visual acceptance |
| Maintainability | CI test discovery, native package/release checks, signed update manifest producer and Rust version consumer | Workflow lint and local script execution; no remote workflow dispatched |
| Security | Reader/server CSP and frame authority, privileged IPC/origin admission, external/native handoffs, sharing cookies/origins, private sync pairing/peer checks, update signatures, HTTPS/redirect policy, attachment and acquisition ownership | No exhaustive fuzzing, dependency advisory audit, packaged exploit acceptance, or physical-device testing |

material broken operation, policy, accessibility or verification boundary;
P3 denotes a localized presentation defect. Evidence labels distinguish executed

The original history-row deletion suspicion was rejected: its backend already
removes all equivalent visits. Explicit bookmark operations in private mode were
not incorrectly reclassified as forbidden operations. Neither observation led
to an unnecessary policy change.

The ownership batch intentionally refuses legacy recovery where only matching
bytes or an unsafe leftover public/hard-linked part can be proved. It preserves
those files and requires explicit manual import/cleanup instead of adopting or
deleting them automatically. Existing consumed library receipts are retained.
During adversarial review, same-inode rewrites, stale retry evidence, lazy Nearby
restart and cancelled-state persistence were explicitly checked in addition to
simple pathname replacement. An isolated host experiment reproduced that an
ordinary same-inode/same-size rewrite with restored mtime evades the older stamp
tuple while changing ctime and bytes. The import path now carries the existing
content identity from before verification through registration: Unix includes
ctime, and Windows filesystem sources retain the existing handle that excludes
write sharing. The full native exploit/regression and Windows behavior remain
unexecuted in this run. New hashing checks cancellation between bounded
reads and before entering archive verification; full-file work stays off global
manager/Store locks in the new ordinary-acquisition verification path. The
existing edition-update path can still hash while holding its import guard;
this review does not claim to have removed that older performance limitation.
The new ordinary-import proof adds a full sequential read before libzim's
integrity pass. Performance and shutdown behavior still require native runtime
acceptance.

## Verification and blockers

Executed so far:

- The JavaScript suite passed all 278 tests, including the final ten CSS checks,
  using Node 26.12.1. This includes the sixteen async usability regressions and
  three stale-external-link regressions.
- All 35 host-only Python regressions passed. No phone, simulator, publisher,
  user profile, library, grant or setting was accessed or modified.
- All 14 update-manifest tests passed, including actual Tauri signing of
  disposable artifacts and exact prerelease/build version binding.
- Two isolated Rust tests passed against the exact production
  `external_link_target` body using cached serde_json 1.0.154 and url 2.5.8.
  They exercised policy changes, confirmation, allowed URLs and rejected
  schemes/credentials. The harness did not launch an OS application or execute
  the full service dispatch/restart path; its owned files were removed.
- Workflow YAML parsing and `actionlint -shellcheck=` passed. Full actionlint
  reports existing SC2094 warnings in checksum commands that explicitly exclude
  their output file; those unrelated commands were not changed.
- Adversarial async tests execute the actual production handler bodies. This is
  useful behavioral evidence, not a substitute for mounted React, native IPC,
  browser layout or end-to-end acceptance.
- Independent review rejected the first contrast correction because iOS's
  whole-control pressed opacity still reduced contrast. The corrected cascade
  covers ordinary primary buttons, reader actions and selected tablet navigation.
  Restoring the broken opacity in an owned temporary copy made the regression
  fail at 2.773:1; that temporary copy was removed. Reader hover brightness was
  also included in the correction and re-review.
- Rust syntax parsing of changed files succeeded using rustfmt without rewriting
  them. This does not type-check, compile, link or execute the Rust changes.

New native regressions include `failed_resume_checkpoint_keeps_a_retryable_row_and_owned_part`,
`cancelled_part_capture_preserves_a_replacement_after_ownership_validation`,
`cancelled_part_cleanup_recovers_its_durable_private_capture_after_restart`,
`cancellation_remains_terminal_when_capture_and_worker_checkpoint_fail`,
`publication_recovery_rejects_byte_identical_replacement_and_preserves_both_files`,
`completed_download_import_rejects_replaced_or_rewritten_publications`, and
`retry_import_refreshes_transient_publication_admission_failure`, alongside
producer-specific BitTorrent/Nearby and external-link tests. These are added
regressions, **not passing native-test results**.

Environment limitations observed during this run:

- This checkout initially had no `node_modules`, `dist` or matched native SDK.
  `npm ci` failed with DNS `ENOTFOUND`. Local cache recovery restored 89 exact
  lockfile packages after verifying their SHA-512 integrity; it did not change
  the dependency manifests/lockfile. Remaining missing packages block a normal
  build. TypeScript reports missing `@tauri-apps/plugin-dialog` and `qrcode.react`.
  After the owner explicitly authorized installing requirements, another
  installation attempt failed identically. The request for network access
  outside the sandbox was automatically rejected because this session disables
  sandbox approval. This is an environment restriction, not missing owner
  authorization. The installed Xcode/compiler, Meson, Ninja and pkg-config are
  already available; required uncached downloads remain blocked.
- The SDK builder first needed the installed Homebrew ICU pkg-config path; after
  supplying it, the pinned Xapian download failed DNS resolution. No substitute
  or unverified SDK was used.
- Offline Rust checking stopped because `cap-fs-ext` was unavailable in the
  registry cache, before compiling the changed Rust code. Rust tests and native
  runtime behavior therefore remain unverified.
- `npm audit --json` failed to reach the registry (`ENOTFOUND`); cargo-deny and
  its local advisory database were unavailable. No current dependency-advisory
  result is claimed. Existing scheduled policy workflows were inspected but
  their remote run results were not verified.
- Computer-use inventory exposed no browser. No current UI screenshots were
  captured, so this is a source-based design review rather than a completed
  visual audit. Physical iPhone work was neither requested nor attempted.

To close the verification gap, restore the exact locked dependencies and matched
SDK using [PACKAGING](../PACKAGING.md), then run the documented frontend build,
all Node/Python tests, native clippy and the Rust library suite. Exercise the
affected runtime paths against an explicitly owned disposable profile. The
remaining interaction checks are:

1. Library/Discover: import and browse grid/list layouts, open facets and search,
   then repeat at narrow widths and native text scales 1, 2 and 3. Source fixes
   are reviewed; rendered clipping, wrapping and focus are unverified.
2. Reader: open an external-link confirmation, change the policy in another
   window and attempt the handoff. Callback behavior is tested; actual native
   dispatch/OS handoff is unverified.
3. Reading list: delay Save while typing and while reopening another editor;
   fail a multi-item removal after its first commit; reject a chosen file read.
   Handler behavior is tested; mounted UI status/focus is unverified.
4. Downloads/Nearby: fail a resume checkpoint; cancel during capture/checkpoint;
   relaunch after interrupted cleanup; replace and rewrite completed outputs
   before verification/registration. Native behavioral regressions are added;
   execution and actual file-preservation proof are unverified.
5. Appearance/settings: inspect light/dark default, hover and pressed controls
   across platform skins, and verify the storage-switch recovery advice. Numeric
   contrast and source rules are checked; screenshots and assistive-technology
   behavior are unverified.
