# Spelling index persistence and archive storage

The app builds spelling suggestions from archive titles using the checked Rust dictionary format. Platform tests found two filesystem failures and a separate startup navigation problem.

* On Linux, opening a directory for traversal produced a descriptor that could not flush a completed index to storage. The app could publish the file and still report failure. Commit `adf3e51` uses a flush-capable directory handle and handles errors before and after publication, including recovery when an existing index must be restored. Tests exercised competing replacement, preservation of unrelated files, failed flush and retry.
* On iOS, reapplying an identical backup attribute at startup changed the archive's status-change time. The spelling index correctly treated that timestamp change as a different archive generation. Commit `6b108e4` checks the descriptor's attribute bytes before writing, still applies changed or missing values, and verifies the required backup policy. An archive touched by the earlier build can need one explicit rebuild. Its prior index is preserved. The fix keeps archive replacement detection intact.

* While the first service response was pending, choosing Settings could briefly open it and then return the reader to Library. Commit `f081a38` preserves explicit navigation through startup and retry, while maintaining session restoration and external launch precedence. A delayed first response reproduced the original failure. The combined application source for the final packages is `29dd6ef7b4f95afe601e88388c6b8a1f052a3503`.

The archive and search dependencies stay pinned to the separately licensed MIT and GPL source trees. Commit `a4d9f06` also replaces handwritten Unix volume queries with typed wrappers for archive-size preflights. On macOS, read-only FAT32 and exFAT disk images exercised the size boundary around 4 GiB, including paths whose last components did not yet exist. The test detached both images. Commit `6d5d6b1` changes only the iOS backup policy and its Swift test relative to that build.
