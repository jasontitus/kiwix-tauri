# Checked byte and substring search

Kiwix and the MCP relay use a local fork of memchr 2.8.3. It searches
checked slices a machine word at a time and counts only exact byte
matches. Multi-byte substring searches use the retained upstream Two-Way
algorithm, with an optional checked pair of candidate bytes for forward
searches. The short scalar scan applies only to haystacks below 64 bytes.
The library forbids unsafe Rust. [Source and license](../../src-tauri/vendor/memchr-2.8.3/SOURCE.txt)

Both application lockfiles change only the source of memchr. The application
reaches it through JSON, XML, regular expressions and gzip among other
consumers. The MCP relay uses it through JSON. The private fork preserves
the crate-root byte functions, iterator behavior, and `memmem` finders.
It omits the unused lower-level architecture APIs and accepts `logging`
as a no-op. The two upstream license texts and COPYING notice are included
in the desktop resource configuration. This change uses no source from
either Zimru workspace.

  diagnostic locations in the published memchr. The checked crate compiled
  with zero under the same default feature configuration. These are crate
  locations compiled before linker elimination.

  The macOS vendor suite passed 32 unit tests and 18 doctests with all
  features and with allocation enabled without std. With all default

  ARMv7 Android.

  9,587,862-byte dump per build. Both versions and both machines matched

  service, acquisition, connector and catalog tests, with six ignored.
  The release relay passed nine tests. A separate relay process accepted

  returned a full multilingual result through an authenticated local

## Performance

The release comparison changes only the source of memchr in the fixture
lockfile. It alternates which binary runs first and reports the median of
nine runs collected after the builds finished. Each run averages 35
operations, with five for the dense two-byte match count. The fixture used
rustc 1.99.1 on Mac and 1.100.0 on Linux. The byte rows scan 16 MiB.
Each JSON workload parses 4,096 mixed-language records. The XML and regular expression workloads
process a generated 16,384-entry feed.

| Workload | Mac ARM64 | Linux x86-64 |
| --- | ---: | ---: |
| Find an absent byte | 0.328 → 1.346 ms | 0.741 → 1.824 ms |
| Find an absent byte from the end | 0.307 → 1.351 ms | 0.647 → 1.877 ms |
| Count dense matches with two needles | 119.906 → 1.109 ms | 81.889 → 2.440 ms |
| Find an absent substring | 0.534 → 1.883 ms | 0.969 → 3.440 ms |
| Parse JSON from a slice | 4.095 → 3.998 ms | 10.118 → 10.172 ms |
| Parse JSON from a buffered stream | 5.171 → 5.062 ms | 6.121 → 5.841 ms |
| Read all XML events | 3.161 → 3.387 ms | 5.245 → 5.102 ms |
| Find all regex matches in the feed | 1.065 → 1.182 ms | 1.434 → 1.766 ms |

The largest checked median was 10.172 ms. The largest median
increase was 0.33 ms for parsing or regex and 2.47 ms for the
16 MiB absent-byte and substring scans. The dense count benefited from summing
matches one word at a time. These are synthetic component workloads
measured with default Cargo release optimization. Mobile timings and
direct libzim comparisons for full reader operations are separate.
[Pinned reader comparison](../benchmarks/2026-11-19-mac-pinned-reader.md)

## Independent review

The source review used base `32601ac` and the 29-file implementation
manifest with SHA-256
`73c32aed30d9da84c48e73aed59514620d4ba676c5f4b5a5c1fd6fa44f280bfd`.
The implementation review covered the tracked edits and new vendor files,
including the byte-mask arithmetic, forward and backward iteration,
substring progress, bounds, feature configurations, consumer APIs and
license provenance. The reviewer modeled 1,179,648 word-mask cases across
16-, 32- and 64-bit word sizes. The review corrected the `alloc` requirements
and documented the omitted low-level APIs and inactive logging feature.
The reviewer rechecked the corrected source and checked the exact final
implementation after the lint fixes.

The work reduces the unsafe dependency inventory. Other application and
dependency boundaries that can process untrusted inputs remain open.
