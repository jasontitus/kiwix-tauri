# macOS print ownership and cancellation

An article print job keeps the originating Tauri window from before rendering begins. The native bridge resolves the AppKit window on the main thread. A missing origin fails. A hidden window or inactive tab prompts the user to activate the original window and retry. An existing sheet or AppKit print operation also produces a retryable error. The app checks the original reader, installation, cancellation and printing policy with the existing commit guard after PDFKit has prepared the operation. The guard is released before entering AppKit's modal API because it may call back into the app event loop. After handoff, the Rust task continues to observe authority and requests cancellation if it retires.

The bridge now exchanges request IDs and numeric status values. Rust retains the private PDF and its admission permit through the matching AppKit completion. A withdrawn queued start releases its lease. Cancellation of an active operation sets the cancel status on that operation's Core Printing session. It never ends a window's arbitrary attached sheet. The delegate callback must match the active operation before it can release the lease. The app also stops logging the article filename from the native bridge.

When the Rust waiter requests cancellation, it waits up to 20 seconds for completion before asking the user to close the dialog. The admission permit bounds retained jobs to two across article PDF operations. The lease remains until AppKit reports completion or the process exits. Exiting with an unsettled operation can leave private scratch for later recovery. The app can request cancellation after preview starts. Any bytes the user already sent to a printer or saved out of the system panel are outside that cancellation contract. [AppKit completion contract](https://developer.apple.com/documentation/appkit/nsprintoperation/runmodal%28for%3Adelegate%3Adidrun%3Acontextinfo%3A%29?language=objc)

The source census covers production Rust in `src-tauri/src` and `kiwix-mcp/src`. It counts 153 blocks in the app and 13 in the relay, down from 158 and 13 at `5437304`. macOS printing removes five blocks in `native_pdf/apple.rs`, including callback pointer dereferences, Rust-box recovery and reading a C error string. The start and cancel calls still cross the native interface. The 41 separate declarations with unsafe syntax are unchanged.

## Verification

The signed arm64 macOS fixture prepared a valid generated PDF through PDFKit. It exercised the exact native bridge with a hidden or busy origin, a missing document, a pending AppKit operation, and a policy denial after preparation. It injected a mismatched completion and repeated cancellation while a prepared operation was marked active. The operation survived past five seconds, preserved an unrelated sheet, and released only after the matching delegate callback. IDs exceeded 32 bits and terminal callbacks were unique. All fixture windows stayed off-screen and the temporary PDF was removed. The fixture binary had SHA-256 `0c7ab80aacbe9ec47c7fe31750ec646f085453f27f92728600429e71ecc43456`.

The fixture uses injected completion events and a test-owned sheet sentinel. Dismissal of a visible AppKit panel, actual spool behavior and printing end to end through the packaged app remain open.

The signed arm64 macOS application test build passed all 27 `native_pdf::` tests and all six PDF export service tests. The new regression withdraws a queued print before native startup and verifies the error and scratch cleanup. Two service tests require temporary loopback archive servers. They passed when rerun with that access. The test binary used the locked `custom-protocol` feature set in the unoptimized test profile and had SHA-256 `4613de0b4136cffcf81f687728b1450b970e2d584ee6f74262a3b7a2bc6015a2`.

## Independent review

Review of the renderer's earlier combined change found that a cancel could end any sheet on the window and that a five-second timer could release the PDF ahead of the AppKit delegate. The print implementation now retires both behaviors. Independent review of this batch found a second poll of a completed Rust receiver and a missing check for another active AppKit operation. The receiver now exits directly on completion or disconnect. The AppKit factory refuses a busy thread, handles a print-operation exception and cleans up only its own unstarted operation. The reviewer verified the three corrected source paths against `5437304fce3fe2df2e80dc18caed0d81a44fe229` and manifest SHA-256 `6bbb268e6eec46c09e42c0a4b4ddfc4363d22cfa6f6d1a00ebb43ce08932c3bf`. Separate preflight verified the fixture and its temporary-file and print-call boundaries.
