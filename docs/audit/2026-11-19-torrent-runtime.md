# Torrent crypto candidate runtime verification

The experiment uses app revision `549f91e2423893cc9c8957b690b1e838d67e6e9f` and the independently reviewed 18-path candidate overlay with manifest SHA-256 `8c1127da6bcaad72d2cb9171a9fc37c31b90924b5bfcac0f67c34eb7ff6676dd`. The candidate feeds librqbit through the app's checked RustCrypto SHA-1 wrapper and uses the existing ring provider for TLS. Its previously verified Cargo graphs across eight targets omit AWS-LC. The Apache-licensed wrapper source, original archive and notices stay with the application-side prototype. [Candidate construction and earlier evidence](2026-11-19-portable-sha1-torrent-crypto.md)

## Linux transfer latency

Both release app-library executables shared each Wikipedia archive, created a new downloader profile, supplied the loopback seeder as an explicit peer, and waited for publication. Each trial verified the complete published bytes, reopened the archive and matched its ID, removed the published test copy, and verified the original remained byte-identical. The test ran on an x86-64 Intel Core i7-8809G without SHA instructions. Build receipts confirm distinct executable hashes, the stock AWS-LC feature and the candidate's patched wrapper. The same two SHA-256-pinned ZIMs, unprivileged loopback-only container, native root bundle and 2 GiB temporary filesystem applied to both variants. Each archive had one warmup per variant and six pairs of measurements with alternating order. All 28 trials passed. [Raw samples and executable hashes](../benchmarks/2026-11-19-torrent-loopback.json)

| Archive and app-observed operation | Stock median | Candidate median | Median paired candidate / stock |
| --- | ---: | ---: | ---: |
| Climate, 8.98 MB, start sharing | 361.64 ms | 360.91 ms | 0.9964 |
| Climate, receive and publish | 593.36 ms | 597.13 ms | 1.0045 |
| Wikipedia 100, 36.52 MB, start sharing | 360.95 ms | 359.95 ms | 0.9960 |
| Wikipedia 100, receive and publish | 739.28 ms | 740.91 ms | 1.0019 |

The largest measured paired median increase was 0.45%. The manager reports terminal progress on 250 ms ticks, so changes shorter than a tick can be obscured. Whole-test median CPU, which also includes archive setup, independent verification and cleanup, was 0.512 s stock and 0.508 s candidate for Climate, and 1.392 s stock and 1.459 s candidate for Wikipedia 100. The loopback timings cover app-visible share and publication latency on this host. Sustained throughput, archive decoding against libzim, physical-device timings and WAN behavior fall outside this experiment. The earlier report measured isolated piece hashing. [Earlier piece hashing results](2026-11-19-portable-sha1-torrent-crypto.md)

Two environment issues surfaced before the final matrix. The bare Docker image failed during construction of the stock HTTP client. Providing the same build-runtime CA bundle to both variants allowed transfers. The first Wikipedia 100 warmup then hit the app's 1 GB projected-free-space check with a 1 GiB test filesystem. The final run used a 2 GiB limit and exercised the normal space check. The matrix excludes samples from both earlier attempts. The benchmark container and its owned runtime scratch were withdrawn after each run.

## Android release package

The Android ARM64 candidate APK has SHA-256 `76f02ff40003d16235659cc434b5c93c1d800e82f903cea371c7e3ebd39ae9a9`. Independent inspection verified its one test signer, Android verifier class, 76 bundled notices, 101-asset frontend input manifest, five ARM64 libraries, 16 KiB alignment, and the app library's strong imports against its API 24 dependency closure. The APK embeds the candidate's patched wrapper and ring-backed configuration. This package still includes native speech libraries and JNI glue.

A disposable API 30 emulator installed the exact package and launched its exported activity. On that image's WebView 83.0.4103.120 it displayed the application's HTML-stage startup diagnostic before reaching Downloads. This observation covers that image and APK combination. An API 35 Google APIs emulator with WebView 124.0.6367.219 reached Downloads, entered the exact magnet and tapped Start download, but the first trial produced no listener connection. The guest and its temporary certificate were retired on each attempt.

The successful API 35 run used a fresh read-only system image. It staged one temporary CA in the guest's user certificate store, verified the installed APK and CA hashes, and used distinct issuers for the two loopback listeners. The runner disabled the guest's external captive-portal probe and confirmed a validated, unmetered default network while IPv4 and IPv6 egress were restricted to loopback. The app's normal download path and certificate verifier ran in the signed APK. [Android certificate store implementation](https://android.googlesource.com/platform/prebuilts/fullsdk/sources/+/refs/heads/androidx-constraintlayout-release/android-35/com/android/org/conscrypt/TrustedCertificateStore.java) · [App connectivity policy](../../src-tauri/plugins/tauri-plugin-kiwix-mobile/android/src/main/java/org/kiwix/mobile/MobilePolicy.kt)

The trusted listener completed TLS 1.3 and received `/announce` with the expected 20-byte info hash `9ece7269bddf24c876ea731ac0bce0e55c518832` and the Kiwix Workbench user agent. It returned HTTP 200. The separately signed listener received an `UNKNOWN_CA` alert and zero HTTP requests. The app was stopped, the emulator exited and its transport and profile were absent. The tracker-event receipt has SHA-256 `f1a238818c568a1402fd7ac46d2bf2e915481fd50309ef3b9738d3c72d8e59bc` and the withdrawal receipt has SHA-256 `ed1380ef1b2bd0da13e237e86365c629d780d755c3745a8d974c6b6bb7fb6478`. These results exercise user-root trust and rejection of an untrusted issuer in the Android release package. Public-root revocation, physical devices and wider TLS algorithm compatibility remain open.

## Review and remaining scope

Independent review covered the app source and package provenance, benchmark instrumentation and raw results, and the scoped TLS runner and receipts. Early Android runner checks stopped on firewall output formatting, a blank forwarding row, and an implicit Android launch that failed to resolve. The corrected runner used an explicit exported activity and verified both tracker outcomes on API 35. The earlier API 35 timeout is recorded separately from the successful run. The pinned source, package, build, runtime and withdrawal receipts are retained in the workspace under `.native/2026-11-19-torrent-runtime`.

AWS-LC removal remains a candidate change. The application uses ring and other native dependencies in this candidate, and its TLS algorithm coverage differs from the stock provider, including P-521 signatures and hybrid X25519MLKEM768 key exchange. The performance switch and the remaining memory-safety work are tracked in the whole-app inventory. [Whole-app worklist](../MEMORY-SAFETY-INVENTORY.md)
