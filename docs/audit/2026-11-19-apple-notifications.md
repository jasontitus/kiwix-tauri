# Apple completion-notification boundary

Notification commands send immutable Foundation data and receive a Foundation object with one retained reference. Rust owns and releases the reply through `Retained<NSData>`. The native bridge checks the 16 KiB request limit before copying input and again before parsing the snapshot. Startup checks the main thread before touching the notification delegate, then publishes the initialized delegate with release and acquire ordering. The wakeup function still holds the service through a weak reference.

The Service submits Apple authorization while the original root action still holds its privacy read lease. It releases the lease before awaiting the response. Each request receives a checked, non-reused ID. The main queue checks the live Rust ticket and the native policy epoch before handing the request to Apple. Cancellation before that check suppresses the authorization request. After admission, the delegate keeps its slot busy until Apple completes the request. Rust retires a dropped waiter immediately. Repeated callbacks cannot finish a newer request or clear its native slot. The Service rechecks the root window, launch and policy authority before writing settings. On iOS it also reacquires foreground authority.

The source census counts **151 production Rust `unsafe` blocks**, down from 159. The application accounts for 138 and the Windows MCP relay accounts for 13. The count excludes dependencies and test-only code. The separate census of unsafe declarations decreased from 41 to 37. The notification module keeps one foreign declaration block for the typed ABI. The app-owned Objective-C++ delegate, journal and filesystem code remain within the memory-safety worklist.

## Independent review

Reviewed base `67ac12b0be8fc83d7cf2b563713b5bc2a3472dc2` and the final source manifest `b82566ce1d1f1e335bfff58510e5b2339db973f6392570a8039fd77a405152ca` for `src-tauri/native/notifications.mm`, `src-tauri/src/notifications.rs` and `src-tauri/src/notifications_service.rs`. Source review covered startup, the retained-object ARM64 ABI, request ownership and lock order, the authorization callback, the Rust policy manager and the Service settings writer. It caught a leftover free call, an admission race that allowed a withdrawn request to show an Apple prompt, and a string conversion that assumed a non-null UTF-8 pointer. The final review verified removal of the free call, the live-ticket and epoch checks, and fallible conversion to UTF-8 data with a fallback message.

The mock authorization run reproduced an unrelated `NSError` with code 1 being reported as an ordinary denial. The fix matches both Apple's notification error domain and its denial code. The independent reviewers verified the source and rerun evidence for the corrected mapping, genuine denial and diagnostic fallback.

## Verification

- The ARM64 macOS app test executable `594e5e390656d28bb04cd844837d7ee1e3bb7ed131e077dd86e448548057835e` passed strict signature verification, six notification tests and one Service settings test. They cover the native headless response and request-size limit, malformed commands, request ID exhaustion, cancelled and duplicate replies, receipt and installation ownership, and a rejected settings transition.
- A standalone signed macOS fixture `0ed89205ba85e23432d12244f8539e12c573a7854ac9885367cdd577a7b1baa6` exercised the production native bridge and the exact Rust wire and request code against a process-local mock notification center. Six groups passed with the Objective-C++ code instrumented by AddressSanitizer and UndefinedBehaviorSanitizer. They cover early installation and headless refusal, cancellation and a protect/unprotect cycle before admission, single-flight behavior, grant and denial, repeated callbacks, cancellation after handoff, localized and unconvertible diagnostics, and policy change before completion. Four Rust threads made 4,000 capability calls during 20 pairs of native configuration changes. The mock used a dedicated empty profile and restored the process-local replacements after the workers finished.
- The same three source files passed the locked offline `custom-protocol` app-library build checks for ARM64 iOS simulator and device targets. The Mac test used Rust 1.99.1. The iOS checks used Rust 1.95.0. Both used Xcode 27 RC.

The fixture exercises callback and policy behavior without system dialogs. Live Apple permission prompts, notification delivery and iOS lifecycle behavior still need runtime verification.
