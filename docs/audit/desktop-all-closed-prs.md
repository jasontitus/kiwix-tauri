# Desktop — all historical closed pull requests

## Scope, census, evidence and limitations

This is an **all-history closed-PR audit**, not a recent sample and not a claim that closed means fixed. The REST pull-request endpoint returned **590 unique closed PRs: 525 merged and 65 closed-unmerged**, #13 through #1551. The original `merged_at`, `closed_at`, head/base SHA, body, labels and URLs are preserved without conflating the two outcomes.

Retrieval used `gh api --paginate --slurp repos/kiwix/kiwix-desktop/pulls?state=closed&per_page=100&sort=created&direction=asc`. Six pages contained **100, 100, 100, 100, 100, 90** items; an explicit request for page 7 returned **[]** at **2026-10-29T17:10:21Z**. No date cutoff or search-result 1,000-item cap was used. Original listing pages, all per-PR file responses (**2,863 changed-file records**), all ordinary PR discussion responses (**1,778 comments**), selected inline review threads, and **284 linked closed issue bodies plus their retained comment pages** are in [the raw evidence](desktop-all-closed-prs.raw.json.xz). The raw artifact records per-request retrieval timestamps, page boundaries, endpoints, current-source hashes and the original public index HTML. The main PR listing was fetched before the first file-response timestamp recorded there; its exact request-start clock was not recorded and is not invented.

### Count discrepancy resolved without dropping history

The [public closed-PR index](https://github.com/kiwix/kiwix-desktop/pulls?q=is%3Apr+is%3Aclosed) reports **588**, matching the issue-endpoint snapshot's 588 PR entries. The pull endpoint additionally returns **[#28](https://github.com/kiwix/kiwix-desktop/pull/28)** and **[#1388](https://github.com/kiwix/kiwix-desktop/pull/1388)**: both closed-unmerged, both ghost-authored, with directly retrievable bodies/files/comments. They are retained here. The precise GitHub indexing reason is **not established**; ghost authorship is an observation, not a proven cause. A separate search-endpoint count request failed with the shared core API rate-limit error; the independent public HTML and exact set difference are retained rather than silently accepting 588 as all history. Genuine issue-only census is the sibling audit's separate 792 items; none of these PRs are mislabeled as issues.

### What was actually reviewed

- **Every one of the 590 full PR bodies**, including empty bodies, unmerged proposals, translations, dependency/CI/release/docs work; every returned file manifest was classified.
- Behavior-relevant diffs/hunks and linked issue discussion were read for the high-risk contracts below (durability, destructive operations, archive exceptions and relative navigation, portable roots, search pagination, external-content blocking, attachment opening, session/tab handling, TTS, OPDS endpoint changes). All supplied patches are retained; this is not a claim every line of every translation or CI diff was manually security-reviewed.
- Ordinary discussions were fetched for **all** PRs; inline review comments were additionally fetched for **36 selected PRs** (numbers are keys under `selected_inline_review_comments` in the raw artifact). Retained is not synonymous with every comment manually read. Relevant portable, Fetch/security, theme and link-kind review concerns are explicitly analyzed below.
- Empty file-list responses for unmerged **#574, #580, #1348, #1509** are recorded as such, not inferred as working changes. Per-file patches can be absent or truncated by GitHub; source inspection and selected diffs are the evidence used for conclusions. No content is fabricated to fill absent patches.
- Current comparison references are [FEATURES](../FEATURES.md), [ISSUES](../ISSUES.md), source modules below, and read-only predecessor source. Those two shared documents still describe the earlier limited audit and contain earlier platform proof; they are not rewritten by this audit. Main integration owns updating shared summaries after all four historical audits land.
- **No builds, tests, formatters, linters, emulator/simulator runs or runtime acceptance were executed by this audit.** Existing runtime evidence is attributed to the supplied documentation, not re-exercised. No application or reference-repository code was changed.

### Portable contract and safety boundaries

Actual #1179 `isPortableMode()` tests `QFileInfo(executableParent, ".portable").exists()` and returns `executableParent/data`; this existence test also accepts a directory, whereas issue #1166 defines an empty **file**. The replacement should state its regular-file/symlink policy explicitly rather than accidentally making arbitrary existing directories activate a mode. Issue [#1166 comment 2268525840](https://github.com/kiwix/kiwix-desktop/issues/1166#issuecomment-2268525840) permits the packager to precreate `data`. Marker handling need not silently create/fall back elsewhere. Bundle/AppImage root resolution and explicit `--data-dir` conflict precedence are not defined by these upstream diffs; use an explicit consistent launch contract, not accidental cwd dependence.

#1209 forces **both** monitor/download root on each portable start; [comment 2353732201](https://github.com/kiwix/kiwix-desktop/pull/1209#issuecomment-2353732201) agrees both controls should be greyed, and [2355185076](https://github.com/kiwix/kiwix-desktop/pull/1209#issuecomment-2355185076) confirms disabled buttons/tooltips. Current upstream `ContentManager::updateLibraryFromDir` scans **direct `*.zim` children only**, not recursion or `.zimaa`. [Issue #461 comment 2348956238](https://github.com/kiwix/kiwix-desktop/issues/461#issuecomment-2348956238) explains the desired drop-content-into-USB workflow without manually generating library.xml. Existing replacement periodic scanning can be reused; identical Qt watcher internals are not required. #1179 discussion explicitly permits reading imported archives outside USB, so do not conflate portable state placement with a new mandatory copy/import sandbox or private/read-only mode.

## High-risk histories that must not become blanket “fixed” claims

### Durable torrent / acquisition

[#1496](https://github.com/kiwix/kiwix-desktop/pull/1496) restores libtorrent jobs by magnet metadata plus **full piece recheck**, forces recheck and initially pauses; it does not persist trusted fast-resume bitmap state. [#1465](https://github.com/kiwix/kiwix-desktop/issues/1465) discussion accepts recheck restoration and defers saved-piece-list optimization. The replacement's `torrent.rs::restore_record` separates deliberate pause, policy-held interruption, verified completion and seeding; `librqbit` replaces libtorrent/aria2, not user-visible durability.

[FEATURES](../FEATURES.md) records the actual **71,363,654-byte independent-peer desktop** proof: graceful exit, manual pause, tampered staging and SIGKILL; restart reused **10,808,390 verified bytes**, fetched **60,555,264** remaining bytes, matched SHA-256/imported, and kept disabled completed-seeding disabled. That was an **immutable pre-mobile-lifecycle binary**. New Android foreground-service and iOS suspension/relaunch code require fresh platform acceptance; neither the PR merge nor earlier desktop transfer certifies them.

[#183](https://github.com/kiwix/kiwix-desktop/pull/183), [#1038](https://github.com/kiwix/kiwix-desktop/pull/1038) and [#1118](https://github.com/kiwix/kiwix-desktop/pull/1118) establish delayed confirmation/action/completion races, active-job restoration and slow-storage UI responsiveness. Native async workers are source counterparts, not evidence of nonblocking all-disk behavior. Required faults: cancel/pause after completion, changed destination while start queued, corrupted staging/checkpoint, missing peer metadata, disk full, write-denied and shutdown persistence errors. Jobs must stay independently visible/actionable; acquisition may upload even when **post-completion** seeding is disabled.

### Destructive deletion, corrupt archives and external execution

[#816](https://github.com/kiwix/kiwix-desktop/pull/816) guards the catastrophic empty-basename `*` deletion described in [#809](https://github.com/kiwix/kiwix-desktop/issues/809); later upstream still uses basename-prefix globs for sidecar/split sets. `library_files.rs` exact-part identity/checksum/capability staging and publication/recovery counterparts are stronger source design, **not exercised destructive-safety certification**. Required sentinels: unrelated same-prefix files, symlink/path replacement, split-part swap, same/cross-volume partial move/trash failure, crash recovery, completed-vs-cancelled ownership. Do not equate checksum integrity with publisher authenticity.

[#830](https://github.com/kiwix/kiwix-desktop/pull/830), [#1086](https://github.com/kiwix/kiwix-desktop/pull/1086), [#1096](https://github.com/kiwix/kiwix-desktop/pull/1096), [#1132](https://github.com/kiwix/kiwix-desktop/pull/1132), [#1174](https://github.com/kiwix/kiwix-desktop/pull/1174) require unavailable/corrupt archives/indexes not crashing reading, search, bookmark population or restart. Search source keeps per-book errors rather than suppressing good mixed-source results. Current server plain-text error responses avoid upstream's unescaped metadata-concatenated HTML pattern; the C++ bridge still requires explicit lifetime/exception review, not a “Rust safe” assumption.

[#1123](https://github.com/kiwix/kiwix-desktop/pull/1123) merged explicit attachment Save/Open (superseding unmerged #1070). Replacement trusted confirmation/signature-MIME allowlist is intentionally narrower than arbitrary OS execution. PDF Preview proof is macOS-only. No output left behind on canceled Save (#1231), no unconfirmed external navigation/attachment execution, and exact resource bytes remain required across platforms.

### WebGL / Fetch / service workers / privacy

[#905](https://github.com/kiwix/kiwix-desktop/pull/905)'s AppImage GPU hack was reversed by [#1478](https://github.com/kiwix/kiwix-desktop/pull/1478); blindly retaining old “fixes” would break maps. [#1481](https://github.com/kiwix/kiwix-desktop/pull/1481) added `SecureScheme`, `LocalAccessAllowed`, `CorsEnabled`, `FetchApiAllowed` and host syntax; [inline review 3067773529](https://github.com/kiwix/kiwix-desktop/pull/1481#discussion_r3067773529) explicitly flags overbroad secure/local permissions. Loopback same-origin Fetch can work without copying those archive-wide trust grants. Sensor prompting, isolation and external resource blocking must survive modern map/worker/WASM content.

[#887](https://github.com/kiwix/kiwix-desktop/pull/887) **did** add `notag=_sw:yes`. [#965](https://github.com/kiwix/kiwix-desktop/pull/965) later removed `query.addQueryItem("notag",...)` while retaining unused `excludeTags`, confirmed in current predecessor `src/opdsrequestmanager.cpp:24-44`. Thus “merged filter fix” is not proof the current app filters SW archives. Replacement server explicitly rejects service-worker scripts; this remains a compatibility boundary, not complete Zimit/SW parity. #1217 private/read-only proposal is unmerged; replacement's independently implemented modes must keep their explicit semantics, not inherit an unmerged promise of zero OS I/O.

### OPDS, search and title/body mismatches

[#1429](https://github.com/kiwix/kiwix-desktop/pull/1429) combines redirect support and endpoint move; [#1446](https://github.com/kiwix/kiwix-desktop/pull/1446) reverts only endpoint portions, and [#1515](https://github.com/kiwix/kiwix-desktop/pull/1515) changes host later. `catalog.rs::fetch_catalog` parses relative links against final `response.url()`; redirect policy rejects unsafe downgrade and limits chains. Final relative-thumbnail/feed/facet URLs must be exercised rather than hardcoding conclusions from one hostname.

Search pagination fixes #628/#844 and endless suggestions #1224 are user contracts, not Qt renderer migration requirements. The documented >=1,000 title-boundary fixture is targeted evidence; stale Enter results, IME/on-screen keyboard, corrupt/no-index mixed books, ranking and exact query/fragment path identity remain acceptance. #1218 itself explicitly uses **single** book selection with hidden select-all; do not misattribute replacement's real multizim expansion to upstream.

Actual files take precedence over titles and speculative bodies: **#625** title says rollback but changes French JSON; **#1042/#1043** unmerged prose is not executed remediation; **#1498** title says OPDS ingest but patch only changes libkiwix API calls and its #1309 reference is a foreground-opening issue; **#1514** includes overlapping theme code besides policy URL; **#1525** body claims broad tab clamps, but retained patch only moves active-index restoration inside restore-enabled branch. #1414 merged suggestion painting caused double rendering fixed by #1430. #1518 inline review notes opening Settings can spuriously reload ZIM views. These are why each row retains original evidence and does not report automatic fix closure.
