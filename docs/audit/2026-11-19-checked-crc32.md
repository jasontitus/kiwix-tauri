# Checked CRC32 loads for gzip and PNG

Workbench uses a local `crc32fast` 1.5.5 for both host and target dependencies. The published ARM64 PMULL and x86 PCLMUL kernels loaded vectors through raw pointers. The local implementation reads bounds-checked little-endian words, then constructs vectors from register lanes. The wider x86 kernels explicitly zero the high lanes of the initial CRC vector. The runtime dispatcher still validates CPU capabilities. The local package keeps the published MIT and Apache-2.0 licenses and uses the app's Rust 1.90 minimum. [Source and bundle notice](../../src-tauri/vendor/crc32fast-1.5.5/SOURCE.txt)

The locked graphs select the same local source for nine target triples covering both macOS architectures, ARM64 iOS and the iOS Simulator, ARM64 and ARMv7 Android, ARM64 and x86-64 Linux, and x86-64 Windows MSVC. Target consumers include the desktop PNG dependency and `flate2`'s gzip checks used by the desktop updater. `librqbit` also builds an optional gzip IP-list loader. Workbench initializes it with the default unset allowlist and blocklist URLs. Host builds use the package for PNG checks during Tauri code generation. The MIT Zimru and GPL Glass engine pins stay in their respective histories. The XZ reader's `crc` package is a separate implementation.

## Verification

The published source and candidate were compiled with Rust 1.100.0 and `--force-warn unsafe_code`. Non-test `crc32fast` diagnostics dropped from 10 to 1 for ARM64 macOS and from 11 to 1 for x86-64 Linux. Each remaining block calls an architecture kernel after the dispatcher's CPU checks. There are no raw-pointer block loads in those kernels. The DEFLATE implementation and other checksum dependencies remain separate review work.

The locked release suite passed 20 tests on the Apple Silicon Mac and 19 on the designated Linux x86-64 host, including unit, exhaustive and documentation tests. Both ran the scalar reference, streaming splits, checksum combination, varying initial values and alignment and length boundaries. The Mac runtime exercised ARM CRC and PMULL. Linux exercised the PCLMUL 128-bit kernel. Its CPU lacks VPCLMULQDQ, so the wider x86 kernels had compile and source coverage in this run. Standalone library checks passed for iOS ARM64, iOS Simulator ARM64, Android ARM64 and Android ARMv7, both with and without default features.

The macOS ARM64 application library test executable built with `custom-protocol` from base `35f1018d0bb02dd69c46e2520547e58158fb0d4b` and the checked dependency. Its signature verified and 27 selected tests passed across updater checks, archive reads and Glass search. The separate updater installation exercise remained skipped. The committed resource map selects both upstream license texts and the source notice for bundling.

Independent review compared the vendored files with the published archive and confirmed lane order, bounded tail handling, feature dispatch, and the consuming packages. The reviewer independently ran five reference tests and 40 Apple ARM64 comparisons with zlib up through 8 MiB. This checkpoint exercises the shipping dependency code and scoped Mac application tests. It leaves mobile and Windows runtime, wide x86 hardware, and updater installation checks open.

## Performance

The native libzim driver supplied the 24 sampled article reads from each of the Climate and Wikipedia 100 archives. To reproduce the 8 MiB of decoded data, remove the response length fields, concatenate the article bytes in the saved order, repeat, and truncate to 8 MiB. Prefix the raw file with the three ASCII bytes `crc` for the unaligned benchmark reads. Gzip-compress the two 4 MiB halves of the payload separately at level 6 with `mtime=0`, then concatenate the two members.

Each gzip driver rejected a corrupt final checksum and a truncated footer, then decoded the valid input and checked the output bytes. The runner compared every timed process's reported CRC with Python's zlib reference. Each case uses 12 alternating before/after pairs after one discarded pair. The gzip operation covers decompression and both member checks, using a reused output allocation. The isolated Mac checksum took longer, with a 0.067 ms increase at 8 MiB. The complete gzip medians remained below 19 ms on both hosts. These measurements cover a standalone gzip operation. Package installation, mobile runtime, and the app's ZIM reader have separate performance evidence.
