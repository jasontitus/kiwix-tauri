## P1 findings

### R1. Migration rollback deletes a pre-existing destination — Reproduced

`src-tauri/src/library_root.rs:348-359,552-581`.

Rollback treats a regular file with the planned name and size as owned by the migration. A publication collision therefore returns “nothing was overwritten,” then rollback deletes the colliding file—even if it existed before this operation. All planned entries are visited, not only successfully published entries. Internal → external with old copies retained → internal is an ordinary collision scenario.

A disposable profile with a valid source and an unrelated same-length destination produced the collision error and `preexisting_destination_exists=false`.

**Fix:** durably record actual publication ownership/identity and remove only those exact objects. Matching names, sizes or content are not ownership.

### R2. Recovery deletes originals without validating their replacements — Reproduced

`src-tauri/src/library_root.rs:387-389,531-548`.

When Store points at the new root, recovery calls `finish_cleanup()`. With remove-old selected, it hashes the old source and deletes it without verifying that the destination cohort still exists, matches the recorded hashes, and is the admitted archive. A missing, corrupt or unavailable removable destination can therefore cause deletion of the last good copy.

A committed-journal probe with the new archive absent reported successful completion, then `old_copy_exists=false`, `new_copy_exists=false`, `journal_exists=false`.

**Fix:** verify the entire replacement before removing any original; preserve originals and the journal on uncertainty.

### R3. Migration rolls back after Store has committed — Source-traced

`src-tauri/src/library_root.rs:350-354`; `src-tauri/src/store.rs:2363-2369,2650-2654`.

Store can atomically replace state, adopt that new state, then return an error because directory synchronization failed. Migration assumes any error means Store was not switched and deletes the published destination. Both saved and live paths can then reference deleted archives, while rollback removes the recovery journal.

**Fix:** distinguish precommit failure from committed/uncertain durability; once Store references the new root, preserve the copies and journal. A directory-sync fault injection is still needed.

### R4. Four LocalSwarm pipelines can deadlock the shared prefetch budget — Source-traced

`src-tauri/src/localswarm/network.rs:37-39,678-710`; `src-tauri/src/localswarm/sources.rs:204-205`.

Four source sessions can each retain a 16 MiB first chunk, exhausting the 64 MiB budget. Each then waits to acquire a second chunk's permit before handing the pending first chunk to the writer. Nothing reaches the writer, so no permit can be released. Cancellation works; forward progress does not. Valid manifests permit this chunk size.

**Fix:** hand off a pending verified chunk before waiting for unavailable lookahead budget, retaining correct byte accounting. Verify with four synchronized sessions and two chunks per session; this scheduling reproduction was not run.

### R5. iOS reconnect admission can cross a private-mode cutover — Source-traced

`src-tauri/src/mobile_service.rs:733-778`, especially `762-775`.

Reconnect decides from settings before awaiting transfer/privacy locks. Settings can finish stopping transfers and commit private mode while reconnect waits. The stale decision then resumes managers without rechecking private mode, lifecycle or auto-resume settings inside the locks. Network admission alone does not enforce those settings.

**Fix:** recompute effective reconnect admission after acquiring the guards and before restarting managers. Verify with a deterministic gate-held private-mode transition.
